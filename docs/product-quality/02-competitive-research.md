# Competitive UX research for Prodwise

Research date: 27 September 2026. Research only; recommendations await architecture/UX consumption and contract freeze. Scope: Linear, Jira/Jira Product Discovery, Notion, Productboard, Aha! Roadmaps. Method: current official help documentation and vendor engineering articles, opened directly after search. No competitor account, authenticated workflow test, comparative speed benchmark, or customer-research claim is implied. These are adjacent product patterns, not a feature-parity scorecard.

The Pattern column records documented behavior. **Why it works, disposition, and Prodwise rationale are our design inference**, not vendor-proven usability outcomes. A source confirms a capability, not that it is appropriate for Prodwise. Plan/role limitations below are retained where they affect interpretation. Directly opened Productboard documentation was updated 16 September 2026; older search extracts describe a different navigation layout and are not used as current placement evidence.

## Decisions to carry into the frozen design contract

1. **Visible scope:** Prodwise → current organization → portfolio or named initiative. One discoverable Administration entry uses explicit Platform / Organization scope. Platform role is not an organization membership.
2. **Task-led first run:** an optional guide and contextual examples over existing data; permission-aware “next action,” useful empty states, no forced tour or invented completion score.
3. **Analysis routes:** Portfolio → initiative list → dedicated initiative detail, with filter/back context. Aggregate → supporting rows/history/observations. No scroll-jump substitute for navigation.
4. **Density through structure:** concise register columns, clear row groups, focused detail panels, and short summaries. Mobile uses list/detail; evidence must not split 27/30 comparison. Density is not tiny type, large card counts, or hiding all detail behind triangles.
5. **Review lifecycle:** facts remain canonical; draft narrative is editable; explicit structured confirmation changes the initiative; Final freezes what management reviewed and becomes the next baseline. Explain these consequences at the relevant action.
6. **Speed with evidence:** measure route transition, server reads, and layout stability before/after. Preserve current scope and trust behavior while improving load work; no unsupported “Linear-fast” claim.

## Boundaries and research limitations

Official docs establish patterns, not superiority or actual task-completion speed. Sidebar arrangements evolve; do not freeze icon position from a cached screenshot. The current Productboard guide differs from older indexed text, and Jira terminology/navigation has moved toward spaces and horizontal tabs. No recommendation imports competitors' permissions, health calculations, destructive record behavior, public sharing, or AI trust model into Prodwise. Those remain governed by Prodwise's approved contract. This artifact introduces no new production data, integration, schema, account, or implementation scope.
